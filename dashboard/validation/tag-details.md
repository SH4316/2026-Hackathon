# 발행 후 태그 세부 정보 편집 검증

2026-10-30 UTC에 Java 21·Node.js 24.22.1·실제 MySQL 8.4를 사용하는 별도 테스트 DB와 패키지 서버 `http://127.0.0.1:8084`에서 검증했습니다. 기존 시연 DB는 사용하지 않았습니다. 이 기록은 이전 [태그별 Jev·Python 정규식 검증](tag-rules.md)의 발행 후 읽기 전용 동작을 대체하며, 이전 결과 파일은 그대로 보존합니다.

## 변경 범위와 동작

`PUT /api/v1/config-versions/{id}/tags/{tagId}`는 현재 선택한 초안·발행 버전의 기존 태그 한 개에 대해 이름·색·설명·예시·판단 참고사항·Jev 프롬프트·Python 정규식만 저장하고 해당 버전의 `revision`을 증가시킵니다. 같은 태그 ID를 가진 다른 버전은 바뀌지 않습니다. 발행된 태그 ID·구성·부모·순서, 버전 ID·이름·상태·활성 여부와 정책은 유지합니다. 구조 필드와 알 수 없는 필드는 거부하며 오래된 revision은 충돌로 처리합니다. 구조나 정책 변경은 초안 복제·저장·발행 경로를 사용합니다.

`MetricSettings.tsx`와 `styles.css`는 발행 상태의 태그 세부 입력, 적용 범위 안내와 **세부 정보 저장**을 제공합니다. 선택한 태그를 저장해도 다른 태그·트리·정책의 미저장 입력은 유지하며, 새 태그는 먼저 **초안 저장**에 포함합니다. 저장 충돌 시 입력과 미저장 상태도 유지합니다. `format.ts`의 트리 정렬과 편집기 순서 변경은 같은 순서 값의 형제를 ASCII 태그 ID로 정렬하므로 이름을 바꿔도 트리 순서가 바뀌지 않습니다. Jev·Python 필드의 원문 보존, 길이 제한, 서로의 독립성과 부모 상속 없음은 계속 적용됩니다. 활성 발행 버전의 저장은 같은 버전 ID와 증가한 revision으로 다음 `classifier-config` 조회에 반영됩니다. 외부 분류기의 설정 재조회·적용은 연결하는 쪽의 책임이며 대시보드가 외부 Jev나 Python 정규식을 실행하지 않습니다.

V6 마이그레이션과 이벤트 저장·조회는 감지 태그에 수집 당시 이름·색을 보관합니다. 기존 연결은 해당 이벤트의 수집 버전에서 채우고 새 수집은 설정과 함께 원자적으로 보관합니다. 이후 세부 정보 수정에도 이력·저장 검색 이벤트의 당시 이름·색은 유지됩니다. 그래프 제목·범례는 선택한 버전의 현재 이름·색을 사용하며 집계 수치와 저장 검색의 이벤트 구성·필터·트리는 바뀌지 않습니다. README와 계약 문서는 이 범위를 반영하며, 이번 문서화에서는 제품 제약·디자인 동작 규칙·화면 명세·검증 기록을 갱신했습니다. 디자인 토큰과 사이드카, 무관한 기존 메타데이터·스키마는 변경하지 않았습니다.

## 검증 결과

- 백엔드 테스트 **60개가 실패·오류·건너뜀 없이 통과**했습니다. 초안·발행 태그 세부 저장과 버전 격리, revision 충돌과 구조 필드 거부, 동시 수정, 활성 설정 갱신, V6 기존 데이터 보존·이력 이름·색 보관, 이벤트 재전송과 집계·스냅샷 보존을 포함합니다.
- 프런트엔드 `npm test` **56개·6개 파일**과 `npm run build`의 타입 검사·프로덕션 빌드를 통과했습니다. 발행 세부 정보 편집과 구조·정책 잠금, 선택 태그 저장 중 다른 미저장 입력 보존, 최신 revision의 전체 초안 저장, 충돌 후 입력 유지와 새 태그의 초안 저장 경로, 같은 순서 값의 형제 이름 변경 후 트리 순서 보존을 확인했습니다. 기존 Vite 번들 크기 경고는 남아 있습니다.
- [실제 API 검사](tag-details-api.json)는 선택한 버전만 변경되고 기존 복제본·트리·정책이 유지됨을 확인했습니다. 활성 분류 설정과 그래프 표시는 갱신되며 집계 수치·기존 이벤트 이름과 색·저장 검색 구성은 유지됩니다. 동시 동일 요청 12건에서 `201` 1건·`200` 11건, Unicode 구간·버전 재해석·안전한 오류 응답도 통과했습니다.
- [최종 브라우저 검사](tag-details-browser.json)는 합성 설정만 생성·게시·활성화했으며 사람이나 이벤트를 만들지 않았습니다. 한글·이모지·공백·줄바꿈과 Python 정규식 원문 보존, 필드·부모/자식 독립성, 발행 후 모든 세부 필드 저장·구조 잠금·revision 증가와 활성 설정 갱신, 먼저 만든 복제본 및 이후 복제본과의 격리를 통과했습니다. 같은 순서 값의 최상위 형제 이름을 사전순이 뒤집히게 수정한 뒤에도 ASCII ID 순서와 자식 위치가 유지되는 것을 최종 패키지에서 추가 확인했습니다.
- [개발 SQL 반복 실행](tag-details-seed.json)은 실제 게시 예시 태그의 이름·Jev 프롬프트를 새 API로 수정해도 기존 감지 태그 연결 507개의 수집 이름·색이 유지됨을 확인했습니다. 이후 SQL 콜백을 다시 실행해 수정한 태그·전체 태그 목록·버전 메타데이터와 revision·활성 버전·기존 수집 이력이 그대로 유지됐습니다. V6가 적용된 별도 실제 MySQL 스키마의 실행 결과이며 Docker 런타임 검증은 아닙니다.
- [패키지 검사](tag-details-package.json)는 9개 SPA 경로, 실제 JS·CSS, 없는 리소스의 `404`, JSON API·Swagger·OpenAPI 상대 서버 및 개발 SQL의 JAR 제외를 통과했습니다. 검증 JAR은 `backend/build/libs/ai-security-dashboard.jar`이며 SHA-256은 `332a29f57b4d7353fdc910d1dd4b0562e946d4a0047ecb5c55d17a0fde8c9e4a`입니다.

## 화면 리뷰와 한계

최종 캡처 `.impeccable/review/tag-details-{draft|published}-{desktop|mobile}.png`의 초안·발행 × 데스크톱 1440px·모바일 390px 4개 화면은 새 리뷰에서 모두 **SHIP**이며 중요한 발견 사항은 없었습니다. 발행 화면의 트리 추가 컨트롤은 보이되 비활성인 것이 의도한 동작입니다. 네 캡처는 저장 완료 상태이며 저장 버튼의 미저장 상태별 활성화나 충돌 회복 자체를 증명하지 않습니다. 해당 동작은 위 행동 테스트와 브라우저/API 결과로 확인했습니다. 기계식 디자인 검사 결과도 발견 사항이 없었습니다.

초안·발행 상태 각각 320·390·768·1280·1440px의 가로 넘침 측정 10건과 390·1440px 설정 영역의 axe 검사 4건에서 넘침·자동 위반·미완료 판정·처리되지 않은 JavaScript 오류는 모두 0개였습니다. 이는 제한된 화면의 자동 검사이며 수동 보조 기술 검증이나 WCAG 전체 적합성 판정은 포함하지 않습니다. Docker Engine을 사용할 수 없어 이미지 빌드·컨테이너 기동·볼륨 재시작은 검증하지 않았습니다. 문서화 점검은 소스·기존 보고서를 확인한 작업이며 앱 테스트나 빌드를 별도로 다시 실행하지 않았습니다.

재실행은 [README의 검증 명령](../README.md#검증-재실행)을 따릅니다. 전용 브라우저 검증은 `dashboard` 디렉터리에서 다음 명령을 사용하며, 합성 설정을 생성·게시·활성화하므로 별도 테스트 서버에 연결합니다.

```bash
DASHBOARD_URL=http://127.0.0.1:8084 \
  BROWSER_REPORT=validation/tag-details-browser.json BROWSER_SCREENSHOT_PREFIX=tag-details \
  node scripts/smoke_jev_prompt.mjs
```
