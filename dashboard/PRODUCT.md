# AI 보안 관제

## Platform
web

## Product
외부 분류기가 전송한 Prompt, 감지 위치와 태그를 사용자 정의 트리 버전으로 요약하고 개인별 이력과 저장된 검색 결과를 확인하는 도구.

## Audience and task
한국어를 사용하는 보안 담당자. 전체 현황에서는 그래프로 탐지량을 확인한다. 상세 검색은 탐지 이력에서 수행하고 조건과 고정 결과를 보존한다. 실제 감지와 태그 부여는 외부 분류기가 담당한다.

## Constraints
Spring/Java 21/Gradle/MySQL와 React/TypeScript/Vite. 로그인 없이 실행하며 수동 새로고침을 사용한다. 사용자 정의 설정은 초안→발행→활성화로 관리한다. 발행 시 태그 ID·구성·부모·순서, 버전 이름과 정책을 고정하며, 태그 이름·색·설명·예시·판단 참고사항·Jev 임계값·Python 정규식·태그 사용 여부와 독립 Jev 프롬프트·출력 연결·판단 사용 여부는 현재 선택한 버전에서 계속 편집한다. Jev 프롬프트 하나가 기존 트리의 여러 태그를 출력할 수 있으며, 같은 버전에서 같은 태그를 출력하는 프롬프트는 그 태그의 임계값을 공유한다. 임계값은 0~1, 소수점 여섯 자리까지 허용하며 빈 값은 미설정이고 0은 유효한 값이다. 같은 태그 ID를 가진 다른 버전에는 적용하지 않는다. 활성 버전은 최대 하나이며 활성 버전의 세부 정보·Jev 설정 저장은 다음 분류 설정 조회에 반영한다. 수집 당시의 태그 이름·색과 저장 검색의 이벤트 구성은 보존한다. 일반 신규 DB는 빈 상태이고 dev 전용 볼륨만 SQL 예시 데이터를 받는다. Prompt 원문과 Unicode 코드 포인트 기준 감지 영역을 저장한다. 태그와 Jev 판단의 사용 여부는 버전별로 독립적이며 기존 항목과 신규 항목은 기본적으로 사용한다. 끈 항목도 설정과 출력 연결을 계속 편집하고 기존 저장 동작으로 적용한다. 부모 태그를 꺼도 자식 설정은 변하지 않는다. 설정 API는 사용하지 않는 항목까지 모두 반환한다. 외부 소비자는 사용 중인 태그의 정규식과, 사용 중인 Jev 판단의 사용 중인 결과 태그만 실행 대상으로 선택해야 하며 사용 중인 결과 태그가 없으면 그 판단을 건너뛴다. 검사 서버는 활성 설정을 기본 30초 간격으로 다시 읽어 태그 정규식과 Jev를 실행하고 규칙 묶음을 확장프로그램에 배포한다. 대시보드는 설정과 관리·시험 프록시를 제공하며 검사·정제는 서버가 담당한다. 내용 판정은 목적지 등급·학습/opt-in 상태와 무관하고 해당 정보는 접속·모델 변경 안내 모달로 알린다.

검사 서버 관리(`/settings/guard`)는 상태·사용자 규칙·Jev 판단 기준·조직 설정·사용자 연결을 관리한다. 서버 Jev의 내부 API 이름 `context_detectors`는 유지하고 조직 트리 Jev 설정과 별도로 둔다. 브라우저는 같은 출처의 `/api/v1/guard/**`만 호출하며 백엔드가 `GUARD_SERVER_URL`과 `GUARD_ADMIN_KEY`로 서버 관리 API를 프록시한다. 루트 Compose는 내부 URL `http://server:8000`과 `PG_ADMIN_KEYS`의 첫 키를 사용하며 키는 브라우저 응답·로그에 노출하지 않는다. 주소·키 미설정 또는 연결 실패는 한국어 503 `GUARD_UNAVAILABLE`이다. 대시보드에는 인증이 없으므로 배포 환경에서 접근을 제한한다. 모델 모드·규칙·조직 상태는 대시보드에서 관리하고 env·YAML은 초기값이다. 엔드포인트 미설정은 모델 비활성으로 표시한다.

정규식 길이는 최대 4,000자다. 검사 서버가 설정된 경우 초안·태그 세부 저장 전에 변경된 비어 있지 않은 `pythonRegex`를 서버 실행 기준으로 검증해 길이 초과·중첩 수량자·문법 오류·빈 문자열 일치를 거부하고 부분 저장하지 않는다. 검사 서버 URL 미설정은 원격 검증 없이 저장하며 설정 후 연결 실패는 저장을 거부한다. 기존 `skipped_regex`는 메트릭 설정의 해당 태그·검사 서버 상태·전체 현황 배너에서 태그 이름과 사유를 표시한다.

조직 기록의 원문 처리 기본값은 `full`이며 `masked`·`off`도 지원한다. 검사 서버는 전송 전 기록 완료를 기다리며 확장프로그램은 `report_status` 실패·누락이나 첨부 기록 실패 시 보류한다. 기록 제외 설정은 별도다. `policy_state_map`은 판정 → 활성 대시보드 정책 상태 ID를 명시적으로 연결하고 기본은 모두 null이다. 전송 선택 `send_action=normal|confirmed|forced`는 V9의 nullable 열에 저장한다. `Event` 목록·상세는 `sendAction`·`fileCount`·`imageCount`를 제공하고 `forced`를 "강행 전송"으로 표시한다. 상세에서는 파일 이름과 이미지 원본의 미리보기·다운로드를 제공하며 `application/octet-stream` 다운로드를 저장된 `media_type`의 blob으로 미리보기한다. 전송 선택은 외부 AI 수신 성공을 증명하지 않는다.

## Design commitment
승인된 계획의 밝은 한국어 관리자 UI. 전체 현황, 탐지 이력, 사람 관리, 메트릭 설정, Jev 설정, 검사 서버 관리, 저장된 검색의 일곱 화면을 일관된 내비게이션으로 연결한다. 감시 연동 메뉴와 화면은 제거하고 기존 `/settings/monitoring` 주소는 쿼리를 보존해 메트릭 설정으로 이동한다. 장식보다 숫자와 표의 읽기 순서, 필터의 명확성, 상태 구별을 우선한다. 제작은 코드로 직접 진행한다.

2026-10-30 탐지 사용 여부 확장은 현재 main의 SafePrompt 어두운 셸과 색 토큰을 기준으로 두 설정 화면의 폼·제목·보조 문구를 맞춘다. 위의 밝은 UI 설명 및 DESIGN.md의 기존 토큰과 현재 구현 사이의 차이는 선행 변경에서 생긴 문서 차이로 기록하며, 이 확장에서 전역 시각 체계나 토큰을 재정의하지 않는다.
