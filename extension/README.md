# Prompt Guard 크롬 확장프로그램 (PoC)

AI 사이트 입력창의 프롬프트를 조직 검사 서버(`server/`)와 독립적인 **기기 내 AI**로 검사하고, 민감정보가 있으면 전송을 멈추고 경고 화면을 띄웁니다.
기존 설치는 서버 검사 ON / 기기 내 AI OFF로 시작합니다. 두 방식은 팝업과 설정에서 각각 켜고 끌 수 있습니다.
확장프로그램 파트 개발의 출발점이 되는 시험용 구현입니다.


## 사이트 모델·계정 설정 확인

지원 사이트에서 선택 모델, 계정·워크스페이스, 요금제, 학습·활동 설정, 임시·시크릿 대화의 **화면에 표시된 상태**를 읽습니다. 입력창 위 위젯의 이용 환경 항목을 펼치면 확인된 값과 확인 불가 항목을 볼 수 있습니다. 서버 연결 없이도 감지합니다.

- ChatGPT·Claude·Gemini 등에 사이트별 선택자를 사용하고, 다른 지원 사이트에서는 모델·설정의 접근성 레이블도 확인합니다. 실제 페이지가 해당 표시를 제공하지 않거나 구조가 달라지면 추측하지 않고 확인 불가로 표시합니다.
- 설정 화면을 열어 스위치가 보일 때 읽습니다. 닫거나 숨기면 확인 불가로 돌아갑니다. 비공개 API 호출, 설정 변경, 쿠키·인증 토큰 수집은 하지 않습니다. 다른 도메인의 설정 화면(예: Gemini의 My Activity)은 현재 읽지 않습니다.
- `Auto`는 화면의 자동 선택 모드만 확인한 것이며 실제 처리 모델은 확인 불가입니다. 요금제와 워크스페이스는 독립적으로 표시합니다. 학습·활동 OFF를 데이터 미보관이나 안전의 증거로 쓰지 않습니다.
- **현재 정책 엔진은 제공사 × 접근 경로 기준입니다.** `docs/ai-model-data-policy.json`의 모델 목록과 예외 메모는 모든 제공사·모델 조합을 검증한 정책표가 아닙니다. 따라서 현재 실제 사이트에서는 모델별 정책이 미확인으로 남으며, 내용 검사가 통과해도 최종 신호는 노란색입니다. 개인정보를 찾았다는 뜻은 아닙니다.
- 노란색에서는 확인 체크 후 해당 전송을 승인할 수 있습니다. 기존 민감정보 차단은 빨간색, 검사 실패·미완료는 회색을 유지합니다. 첨부 파일에도 같은 확인 절차가 적용됩니다. 전체 프롬프트 검사 스위치를 끄면 이 검사도 해제됩니다.
- 모델·설정·계정 표시·대화 경로가 바뀌면 기존 검사 결과와 전송 승인을 무효화합니다. 전송 직전에도 화면을 다시 읽습니다. 감지한 정보는 탭 메모리에만 두고 검사 서버나 확장 저장소로 보내지 않습니다.
- localhost는 기존 테스트 페이지용으로 명시적인 테스트 환경 취급을 합니다. 실제 사이트에는 이 예외가 없습니다.

검증: `npm run e2e:context`는 합성 DOM과 실제 확장을 로드한 Chromium에서 감지·색상·전송 확인·파일·변경 시 승인 취소를 검사합니다. 외부 AI 사이트로 접속하거나 전송하지 않습니다. **로그인된 실제 서비스 화면의 선택자 호환성은 별도 점검이 필요합니다.**

## 기기 내 AI (Qoamo)

서버 코드를 변경하지 않고 확장프로그램 안에서 `atonlee/Qoamo-PII-Decision` INT8 ONNX를 실행합니다.

### 준비 및 사용

```bash
cd extension
npm ci
npm run build:ai
```

Chrome 116 이상에서 이 `extension` 폴더를 압축해제된 확장프로그램으로 로드(기존 설치는 새로고침)합니다.
팝업의 **기기 내 AI 검사**를 켜면 약 **266 MB**의 가중치를 한 번 다운로드합니다.
진행률 → 무결성 확인 → 모델 로딩 → **준비 완료**가 표시됩니다. 실패하면 **모델 준비 다시 시도**를 누릅니다.
첫 준비에는 인터넷이 필요하지만, 완료한 모델은 Cache Storage에 보관되어 브라우저 재시작 후에도 오프라인으로 실행됩니다.
확장프로그램 삭제나 브라우저 데이터 삭제로 캐시가 없어지면 다시 다운로드해야 합니다.

| 서버 검사 | 기기 내 AI | 동작 |
|---|---|---|
| ON | OFF | 기존 서버 검사. 연결 실패·미완료 시 전송 보류 |
| OFF | ON | 기기 내 AI + 내장 기본 규칙만 사용. 검사 서버로 원문을 보내지 않음 |
| ON | ON | 서버와 기기 내 AI가 각각 검사하고 더 엄격한 판단 적용. 네트워크 연결 실패·시간 초과 시 기기 내 검사로 계속 |
| OFF | OFF | 검사 방법이 없어 전송 보류. 검사 없이 보내려면 별도의 전체 **프롬프트 검사** 스위치를 꺼야 함 |

- 서버 인증 실패(401), 서버 오류(5xx), 잘못된 응답, 서버 검사 미완료는 로컬 통과로 덮지 않습니다.
- 기기 내 AI가 켜져 있으면 다운로드·로딩·실패·시간 초과 동안 통과시키지 않습니다. AI 준비가 끝나면 입력 내용을 다시 검사합니다.
- 서버 없이 동작할 때는 **내장 기본 규칙과 이 브라우저의 개인 정규식 규칙**을 사용합니다. 서버의 조직별 사용자 규칙·문맥 탐지·감사 기록까지 대체하지 않습니다. 위젯에 검사 출처를 표시합니다.
- 개인정보의 존재·등급을 판단하는 모델입니다. **정확한 위치를 반환하지 않습니다.** AI만 감지한 경우 문서 전체 경고를 표시하며, 가짜 위치나 마스킹 구간을 만들지 않습니다. 파일 첨부에도 동일하게 적용됩니다.
- 안전 다듬기는 위치가 확인된 기존 규칙과 개인 정규식 규칙의 값을 치환하고, 최종 정제문을 AI로 다시 검사합니다. 이름 등 AI만 감지한 부분은 직접 수정해야 할 수 있습니다.
- 모델 오류를 포함한 검사 미완료는 회색으로 전송을 보류합니다. 기존의 확인 후 전송 흐름은 완료된 경고·차단에만 적용됩니다.
- 스위치·서버 주소·API 키 변경은 이전 검사 결과·전송 승인을 무효화합니다. AI/전체 검사를 끄면 Worker를 종료하고 모델 메모리를 해제합니다. 가중치 캐시는 재사용을 위해 남습니다.

### 실행 구조와 배포

```text
content / files → background (서버·로컬 결과 조합)
                    ├─ 기존 /v1/inspect, /v1/sanitize
                    └─ offscreen 문서 → 전용 Worker → ONNX Runtime WASM + 토크나이저
```

- ONNX Runtime Web 1.31.1, Tokenizers.js 0.2.0의 JS/WASM은 `npm run build:ai`로 `vendor/ai`에 로컬 번들합니다. 원격 실행 코드는 로드하지 않습니다. 생성 파일은 Git 제외이므로 배포 폴더를 만들 때 빌드가 필요합니다.
- 모델·토크나이저·판정 설정은 커밋 `a7650cb1186f65c506dd2a7b3d80c3b6bade85e0`에 고정합니다. 가중치는 크기와 SHA-256을 확인한 후 캐시합니다. 출처·라이선스는 `vendor/qoamo/README.md`를 참고하세요.
- 프롬프트·판정 결과는 저장하지 않습니다. 저장되는 것은 모델, 설정, 텍스트 없는 준비 상태·기존 횟수 통계입니다. 다운로드는 Hugging Face/CDN에 접속하지만 입력 내용은 보내지 않습니다.
- Chromium MV3 `offscreen` / `WORKERS`를 사용합니다. `unlimitedStorage`는 대용량 모델 캐시를 위한 권한입니다. CSP에서 번들된 WASM 실행만 허용합니다.
- WASM CPU를 사용하므로 WebGPU가 없는 기기에서도 실행됩니다. 동시 추론은 1개, 탭별 대기 요청은 최신 것만 유지합니다. 준비 제한 6분, 개별 추론 작업 제한 2분(대기 시간 제외)이며 초과 시 Worker를 종료하고 전송을 보류합니다.
- 긴 입력은 최대 1,000 Unicode 문자, 160자 중첩으로 나눠 모든 조각을 검사합니다. 가장 엄격한 판단을 적용합니다. 한 요청은 최대 50,000 UTF-16 코드 단위이며 매우 긴 파일은 기기 성능에 따라 시간 제한에 걸릴 수 있습니다.

### 검증

```bash
npm test                   # 토크나이저/판정 기준 Python 참조 비교, 결과 조합·실패 처리, 토큰 복원
npx playwright install chromium
npm run e2e:ai             # 실제 ONNX + 실제 확장프로그램, 첫 실행은 모델 다운로드
# 테스트 전용 프로필을 재사용하면 모델 다운로드를 줄일 수 있습니다.
QOAMO_TEST_PROFILE=/tmp/pg-ai-test npm run e2e:ai
```

Chromium 버전을 바꾼 뒤에는 새 테스트 프로필을 사용하세요.

`e2e:ai`는 서버 없이 한국어·영어 추론, 테스트 서버와 판정 결합, 서버 연결 실패,
AI만 감지한 프롬프트·파일 경고, 스위치 변경 후 이전 승인 무효화,
인터넷 차단 및 브라우저 재시작 후 모델 재사용을 확인합니다. 합성 입력만 사용합니다.
화면 캡처는 `tests/ai-shots/`에 생성합니다.
테스트 도구는 Playwright 1.56.1(Chromium 141)로 고정했습니다. 기존 PDF 라이브러리의 `Uint8Array.toHex()` 사용 때문에 구형 테스트 브라우저에서는 PDF 회귀 테스트가 실패합니다.
기존 서버 전용 회귀 테스트는 아래 `npm run e2e`를 사용합니다.

## 동작

아래 서버 설명은 기본 설정(서버 ON / 기기 내 AI OFF) 기준입니다. 기기 내 AI를 켰을 때의 동작은 위 표를 따릅니다.

| 상황 | 동작 |
|---|---|
| 입력 중 | 0.7초 쉬면 검사, 오른쪽 아래 배지로 상태 표시(통과·확인 필요·민감정보 있음·검사 불가) |
| Enter·전송 버튼 | 전송 직전 텍스트가 **검사 완료 + 통과**일 때만 그대로 전송. 아니면 막고 경고 화면 |
| 빨강(차단) | 탐지 항목·위치 표시, [안전 다듬기] → 경고 창이 닫히고 위젯이 정제 미리보기 → [입력창에 넣기] → 사용자가 확인 후 직접 전송(그때 다시 검사). 정제 경로는 위젯 하나뿐입니다 |
| 노랑(확인) | 동의 체크 후에만 "확인 후 전송" 가능 |
| 회색(검사 불가) | 서버 연결 실패·시간 초과·모델 미완료. **전송 보류**, 자동 폴백 없음 |

- 입력이 바뀌면 이전 결과와 전송 승인을 무효화하고, 늦게 도착한 응답은 버립니다(`input_version`).
- 한글 IME 조합 중 Enter, Shift+Enter 는 가로채지 않습니다.
- 사이트 주소로 전송 대상(`destination`)을 정합니다. 요금제·계약은 알 수 없으므로 항상 `consumer` 로 보내고, 서버는 이 값으로 정책을 완화하지 않습니다.
- 경고 화면은 Shadow DOM 으로 사이트 CSS 와 분리했고, 사용자 텍스트는 `textContent` 로만 그립니다.
- 원문은 확장프로그램 저장소·콘솔에 남기지 않습니다. 서버 주소·API 키·검사 설정·텍스트 없는 AI 준비 상태와 횟수만 `chrome.storage.local` 에 저장합니다.

## SafePrompt 위젯 (입력창 신호등)

입력창 위에 붙는 신호등 위젯입니다. 색은 [BRAND_GUIDELINES.md](../BRAND_GUIDELINES.md)의 토큰을 따르고, 시스템 테마(다크/라이트)에 맞춰 바뀝니다.

| 신호 | 표시 | 할 수 있는 것 |
|---|---|---|
| 🔴 Tier 1 차단 | 탐지 항목 요약 | [안전 다듬기], [그래도 전송](확인 후), 칩을 눌러 자세히 보기 |
| 🟡 Tier 2 주의 | 탐지 항목 요약 | 위와 같음 |
| 🟢 Tier 3 안전 | 검사 통과, 또는 "정제 완료" | 정제 후에는 [입력창에 넣기] 뒤 직접 전송 |
| ⚪ 검사 불가 | 서버 무응답·미완료 | 전송 보류(자동 폴백 없음) |

- **입력 즉시 임시 표시**: 브라우저 안의 규칙 엔진(`@prompt-guard/rules`)이 서버 응답 전에 "(서버 확인 중)"으로 먼저 알려 줍니다. 전송 허용 근거는 계속 서버의 '검사 완료 + 통과'뿐입니다.
- **안전 다듬기 → 미리보기 → 입력창에 넣기**: 입력창은 그대로 두고 위젯에 토큰이 들어간 문장을 미리 보여 줍니다. [입력창에 넣기]를 누르면 정제문을 입력창에 넣고, **전송은 사용자가 직접** 합니다. 사이트(ChatGPT 등)는 내부 상태를 늦게 갱신해서, 넣자마자 대신 전송하면 화면은 정제문인데 원문이 나가는 일이 실제로 재현되었기 때문입니다. [원문으로 되돌리기]도 있습니다.
- **답변 복원**: 서버는 복원 매핑을 주지 않으므로, 브라우저가 서버와 같은 규칙으로 토큰 번호를 매기고 **서버 정제문과 한 글자도 다르지 않을 때만** 매핑을 믿습니다. 정제해서 보낸 뒤 새로 생긴 답변의 `[EMAIL_1]` 같은 토큰을 원래 값으로 바꿔 점선 밑줄로 표시합니다. 매핑은 탭 메모리에만 있고 새로고침하면 사라집니다.
- **파일**: 첨부하면 먼저 "검사하는 중"을 보여 주고, 끝나면 결과를 알려 줍니다. 파일은 올라가기 전에 멈춰 두었다가, 사용자가 허락한 경우에만 사이트로 넘깁니다.
  - 텍스트·코드 파일과 **글자가 있는 PDF**(pdf.js로 글자를 뽑음)는 내용을 서버에서 검사합니다. **민감정보가 있으면 어디에 있는지**(PDF는 쪽 번호, 텍스트는 줄 번호와 앞뒤 글자)를 보여 주고 **"그래도 진행할지"** 묻습니다. 진행하려면 확인 체크가 필요하고, [첨부 취소]나 Esc는 취소입니다. 없으면 묻지 않고 "검사 완료, 민감정보 없음"을 표시합니다.
  - **글자로 된 문서도 PDF처럼 검사합니다.** Word(`.docx`·`.docm`), Excel(`.xlsx`·`.xlsm`), PowerPoint(`.pptx`), 한글(`.hwpx`), OpenDocument(`.odt`·`.ods`·`.odp`), `.rtf`는 안의 글자를 뽑아 검사하고, 민감정보의 **위치를 문단·머리글·메모(Word), `시트이름!셀`(Excel), `슬라이드 n`·노트(PowerPoint), 문단(한글·ODF)**으로 알려 준 뒤 "그래도 진행할지" 묻습니다. Word의 변경 추적으로 지운 글자와 메모, Excel의 모든 시트, PowerPoint의 발표자 노트까지 확인합니다. 외부 라이브러리 없이 ZIP과 XML을 직접 읽습니다(`src/office.js`).
  - **읽을 수 없는 파일**(구형 `.doc`·`.xls`·`.ppt`·`.hwp`, 암호가 걸린 문서, 글자가 없는 문서, 음성·영상·이미지·스캔본 PDF·읽지 못한 PDF·너무 큰 파일)은 "읽을 수 없는 파일이지만 안전한지 알 수 없습니다. 그래도 진행할까요?"라고 묻습니다. 음성은 음성 인식(STT), 이미지는 글자 인식(OCR) 서버가 있어야 분석할 수 있습니다. 설정에서 "읽을 수 없는 파일은 묻지 않고 바로 막기"를 켤 수 있습니다.
  - 큰 PDF는 "PDF 글자를 읽는 중… (n/N쪽)"으로 진행을 보여 주고, 45초가 넘거나 30MB를 넘으면 중단하고 "읽을 수 없는 파일"로 묻습니다. 글꼴이 들어 있지 않은 옛 한글 PDF를 위해 한글 문자표(`vendor/pdfjs/cmaps`)를 함께 둡니다.
  - 내용이 50,000자를 넘으면 나눠서 최대 30만 자까지 모두 검사합니다. 검사 서버가 응답하지 못하면 묻지 않고 막습니다(자동 폴백 없음).
  - 여러 파일을 한꺼번에 올리면 확인 창 하나에 모아 보여 주고, 진행과 취소는 전체에 적용됩니다.
- **그래도 전송**: 확인 체크를 해야만 그 한 번의 전송이 나갑니다.
- 팝업에 이 브라우저에서 막은 횟수·다듬은 횟수·강행 횟수가 표시됩니다(어디로도 전송하지 않음).

## 내 정규식 규칙 (개인 규칙)

설정 화면 아래쪽 **내 정규식 규칙**에서 조직 규칙 외에 이 브라우저에서만 추가로 찾을 형식(사번·과제번호 등)을 정합니다.

| 항목 | 설명 |
|---|---|
| 이름 | 경고 화면·위젯에 `사번(개인 규칙)` 처럼 표시 |
| 정규식 | Python 문법(`\d` `\w` 는 한글·전각 숫자 등 Unicode 포함). 서버 사용자 규칙과 같은 제한: 300자 이하, 빈 문자열과 일치 금지, 중첩 수량자 `(a+)+`·이름 그룹·인라인 플래그 `(?i)`·역참조 금지 |
| 조치 | 치환 필요(mask) · 확인 필요(warn) · 전송 불가(block) |
| 토큰 이름 | 치환 시 `[MY_<토큰>_1]`. 서버 토큰과 겹치지 않게 `MY_` 를 항상 붙임 |

- **시험** 버튼으로 저장 전에 시험 문장에서 일치 위치를 확인합니다. 시험 문장은 저장하지 않습니다.
- 서버는 개인 규칙을 모릅니다. 서비스 워커가 서버의 `/v1/inspect`·`/v1/sanitize` 응답에 개인 규칙 탐지를 더해 판정을
  **강화만** 합니다(서버 탐지와 겹치는 구간은 서버 결과를 그대로 씀). 개인 규칙으로 조직 규칙을 끄거나 약하게 만들 수 없습니다.
- 안전 다듬기는 서버 정제문에 남은 개인 규칙 구간을 원문 순서대로 `[MY_..._n]` 으로 치환하므로 답변 복원도 그대로 동작합니다.
- 입력 즉시 표시(브라우저 규칙 엔진)에도 들어가고, 규칙을 바꾸면 열려 있는 사이트에 바로 반영됩니다.
- 규칙(이름·패턴)만 `chrome.storage.local` 의 `personalRules` 에 저장되고 서버로 보내지 않습니다. 따라서 서버 감사 이벤트·대시보드에도 집계되지 않습니다.
  조직 전체에 적용할 규칙은 대시보드의 사용자 규칙(`/v1/admin/custom-rules`)으로 추가하세요.

## 로컬 모드와 조직 관리 모드

| | 로컬 | 조직 관리 |
|---|---|---|
| 조건 | 등록 코드로 연결하지 않음 | 서버 주소를 저장한 뒤 조직 서버(대시보드 연동)의 등록 코드로 연결 |
| 서버 검사 | 켜고 끌 수 있음 | **항상 켜짐**(대시보드 규칙이 서버에서 적용되므로 끌 수 없음) |
| 자체 판단 | 기기 내 AI·개인 정규식·내장 규칙 | 같음. 서버 결과(대시보드 규칙 포함)와 합쳐 더 엄격한 쪽 적용 |
| 서버 연결 실패 | 기기 내 AI 가 켜져 있으면 기기 내 검사로 계속 | **전송 보류**(조직 규칙을 적용하지 못했으므로 기기 내 검사만으로 통과시키지 않음) |
| 기록 | 없음 | 전송·파일 첨부 직전 검사만 조직 대시보드에 기록(원문 처리는 조직 설정) |

설정 화면의 "대시보드 연결"과 검사 방식 안내에 현재 모드가 표시됩니다. 입력 중 검사는 `context.stage: "draft"`,
전송 직전·파일 첨부 검사는 `"submit"` 으로 보내 조직 서버가 타이핑 중 검사를 대시보드에 중복 집계하지 않게 합니다.

## 대시보드 연결

관리자가 대시보드 사람 화면에서 발급한 **연결 정보**(`https://검사서버주소#ABCD-EFGH`)를 설정의 "대시보드 연결"에 붙여 넣고
**연결**을 누르면, 검사 서버 주소를 저장(필요하면 접근 권한 요청)하고 바로 등록합니다. 코드만 받았다면 검사 서버 주소를 먼저 저장한 뒤 코드를 넣습니다.

설정 화면 맨 위 **대시보드 연결**에 관리자가 대시보드에서 발급한 등록 코드(`ABCD-EFGH`)를 넣으면,
서버가 발급한 개인 토큰이 API 키 자리에 저장되고 검사 기록이 대시보드에 그 사용자 이름으로 집계됩니다(원문은 저장되지 않음).
**연결 해제**는 서버에서 토큰을 해지하고 이 브라우저의 토큰을 지웁니다. 서버 주소를 먼저 저장해야 합니다.

## 실제 사이트에서 확인하기

확장프로그램은 실제 전송 상태로만 동작합니다(테스트 모드 없음). 실제 사이트는 가로채기에 실패하면 입력한 문장이 그대로 AI 에 전송되므로 아래 순서를 지킵니다.

1. AI 사이트에 로그인하고 SafePrompt 위젯이 입력창 옆에 나타나는지 확인
2. 무해한 문장(예: "확장프로그램 점검 문장")으로 Enter·전송 버튼이 정상 전송되는지 확인
3. 가짜 값(`AKIAIOSFODNN7EXAMPLE`)을 넣고 Enter·전송 버튼 클릭이 모두 막히고 경고 화면이 뜨는지 확인. 막히지 않으면 가짜 값이 전송된 것이므로 해당 사이트의 선택자를 고칩니다.

| 사이트 | 입력창 | 전송 버튼 | Enter 가로채기 | 경고(Enter) | 경고(클릭) | 비고 |
|---|---|---|---|---|---|---|
| Gemini | ✓ | ✓ `aria-label*="보내기"` | ✓ | ✓ | ✓ | |
| Perplexity | ✓ | ✓ `aria-label*="제출"` | ✓ | ✓ | ✓ | |
| Grok | ✓ | ✓ `aria-label*="제출"` | ✓ | ✓ | ✓ | |
| Qwen Chat | ✓ | ✓ `aria-label*="보내기"` | ✓ | ✓ | ✓ | |
| Kimi | ✓ | ✓ `.send-button-container`(div) | ✓ | ✓ | ✓ | 제한 등급이라 무해한 문장도 확인 화면 |
| ChatGPT | - | - | - | - | - | Cloudflare 사람 확인에 막힘 → 로그인 후 재확인 필요 |

사이트 화면 구조는 자주 바뀌므로 개편 후에는 다시 점검하세요. UI 언어(한국어·영어)에 따라 `aria-label` 이 달라집니다.

## 지원 사이트와 한계

`manifest.json` 의 `content_scripts.matches`: ChatGPT, Claude, Gemini, Copilot, DeepSeek, Kimi, Mistral, Perplexity, Grok, Qwen, Meta AI, 그리고 테스트용 localhost.

- 실제 사이트 검증 현황은 위 표를 참고하세요. 입력창(textarea·contenteditable)과 전송 버튼(`data-testid="send-button"`, `aria-label` 의 Send·전송·보내기)을 넓게 찾지만, 사이트 개편 시 `src/sites.js` 의 선택자를 고쳐야 합니다.
- 사이트가 isTrusted 이벤트만 받거나 별도 단축키·음성 입력·파일 첨부로 보내는 경로는 막지 못합니다.
- 서버 판정은 "검사 결과"이고, 실제 전송·차단 이벤트를 서버로 보내는 계약은 아직 없습니다(`server/docs/api-contract.md`). 팝업의 횟수는 이 브라우저에만 저장합니다.
- 구형 이진 문서(`.doc`·`.xls`·`.ppt`·`.hwp`)와 암호가 걸린 문서는 읽지 못합니다(`.docx`·`.hwpx` 등으로 저장하면 검사됩니다). 문서 안에 들어 있는 그림의 글자는 읽지 않습니다.
- 음성·영상·이미지·스캔본 PDF는 내용을 분석하지 않고 "읽을 수 없는 파일, 안전한지 모름"으로 묻습니다(STT·OCR은 서버 쪽 후속 과제). 한글 PDF는 글꼴에 따라 글자를 못 뽑을 수 있습니다. 답변 복원은 새로고침하면 사라집니다.
- 답변 영역 선택자(`src/sites.js`의 `RESPONSE_SELECTORS`)는 실제 사이트에서 검증하지 않았습니다.
- 기본 서버 권한은 `127.0.0.1`, `localhost` 입니다. 다른 서버 주소는 설정에서 저장할 때 권한을 요청합니다. 원격 서버는 HTTPS 를 쓰세요.
- 아이콘 이미지는 아직 없습니다(Chrome 기본 아이콘).

### 사이트 진입 정책 경고

`src/entry-policy.js`는 두 경우에 안내 모달을 표시한다. **입력 데이터 필수 수집 + 모델 학습 거부 불가**가 공식 정책으로 확인되면 빨간색 진입 경고를, **페이지에서 학습·모델 개선 옵션 ON을 직접 관측**하면 노란색 학습 옵션 경고를 표시한다. ON 경고는 옵션 상태에 대한 안내이며 실제로 해당 대화가 학습에 사용됐다고 단정하지 않는다. 저장 기간이 있다는 이유, 학습 기본값이 ON이라는 이유, 화면에서 토글을 찾지 못했다는 이유로는 표시하지 않는다. 기존 이용 환경 미확인 노란색 표시와 전송 검사는 별개다.

필수 수집·학습 거부 불가 조건으로 확정한 사이트는 없어 해당 정책 목록은 비어 있다. 별도로 지원 사이트에서 학습 ON 옵션을 관측하면 학습 옵션 경고는 표시된다. 2026-10-30 확인: [Kimi](https://www.kimi.com/user/agreement/userPrivacy?lang=en-US&version=v2)는 고객센터 요청을 통한 학습 거부를 안내하고, [DeepSeek](https://cdn.deepseek.com/policies/en-US/deepseek-terms-of-use.html)도 학습 거부 설정을 안내한다. [Grok](https://x.ai/legal/faq)은 비로그인·지역별 예외가 있으나 현재 관측 정보만으로 해당 조건을 확정할 수 없어 제외한다. 전체 데이터 수집이 없다는 뜻은 아니다.

정책을 추가할 때는 공식 출처, 확인일, 적용 호스트·소비자 경로, 필수 수집 및 학습 거부 불가 근거를 함께 검증해야 한다. 조직 계정, 학습 OFF 또는 임시 대화가 관측되어 정책과 충돌하면 모달 대상에서 제외한다. 필수 수집 경고는 문서 진입당 한 번 표시한다. 학습 ON 경고는 동일 상태에서 반복하지 않지만, 실제 OFF 후 다시 ON, 임시 대화 해제, 관측된 계정 변경 시 다시 평가한다. 숨겨진 옵션을 다시 열었다는 이유로는 반복하지 않는다. 새로고침/새 탭에서는 다시 평가한다. SPA 내부 이동에서는 반복하지 않는다. 확장 OFF일 때는 표시하지 않으며 기존 확인창을 덮어쓰지 않는다. 안내 닫기는 전송 승인이 아니다.

`npm run e2e:entry`는 필수 수집 정책 미확인 시 모달 제외, 가상 검증 정책의 진입 UI·키보드·표시 횟수, 그리고 실제 확장을 로드한 합성 페이지에서 학습 ON/OFF·숨김·임시 대화·조직 계정·확장 OFF·SPA·새로고침 동작을 확인한다. 가상 정책은 테스트에서만 주입하며 확장 번들에는 포함하지 않는다.

### 외부 AI 서버 보관 안내

검증 패널에 “외부 AI 서버 잔존 가능 · 보관 기간 미확인”을 표시한다. 텍스트 검증·강제 전송·파일 첨부 확인창과 학습/진입 안내에는 전송한 대화·파일이 **외부 AI 제공사 서버**에 남을 수 있다는 설명을 함께 보여 준다. 학습 OFF·임시 대화·대화 삭제를 즉시 삭제 또는 미보관으로 해석하지 않는다. 서버는 Prompt Guard 검사 백엔드가 아니라 전송 대상 AI 서비스의 서버를 뜻한다.

현재 계정의 보관 기간·삭제 예외를 확인하는 API나 계약 정보는 없으므로 기간을 추정하지 않고 미확인으로 표시한다. 조직·유료 계정에도 미보관을 추정하지 않는다. 안내는 기존 검증 화면 안에 추가되며 새로운 팝업을 유발하거나 검사 판정·전송 동의 조건을 바꾸지 않는다. 로컬 시험 페이지에는 외부 서비스 보관 안내를 표시하지 않는다.
