# SafePrompt — 탐지 엔진 & 신호등 판정 체계

> 이 문서는 SafePrompt의 프롬프트 검사 흐름, 신호등 판정 규칙, 그리고 대시보드에서 가능한 커스터마이징 범위를 설명합니다.

---

## 1. 신호등 판정 개요

SafePrompt는 프롬프트를 검사해 네 가지 신호로 결과를 반환합니다.

| 신호 | 색상 | 의미 | 발생 조건 |
|------|------|------|-----------|
| `GREEN` | 🟢 | 통과 | 검사 완료, 내용 기준 `allow` |
| `YELLOW` | 🟡 | 확인 필요 | `mask`·`block` 없이 `warn` 대상이 있음(또는 조직 Jev의 근거 위치 미확인) |
| `RED` | 🔴 | 민감정보 있음 | 내용에 `mask` 또는 `block` 대상이 하나라도 있음 |
| `GRAY` | ⬜ | 검사 미완료 | 검사·모델 실패 또는 조직 규칙을 적용하지 못함 |

판정값은 `server/app/schemas.py`의 `Decision` · `Signal` enum으로 정의되어 있으며, `pipeline.py`에서 탐지 결과를 합산해 최종 신호로 변환합니다.
전송 대상 등급, 선택 모델, 학습·opt-in 상태는 판정에 영향을 주지 않습니다. 확장프로그램은 사이트 접속·모델 변경 시 이 정보를 안내 모달로 보여 주며, 확인하지 못한 항목도 명시합니다. 환경 미확인만으로 노랑이 되지 않습니다.
검사 완료된 빨강은 `block`을 포함해 사용자 확인 후 강행 전송할 수 있습니다. 조직 관리 상태에서는 전송 전에 대시보드 기록 결과를 확인하며, 기록 실패·응답 누락은 회색 보류입니다(`report_text=off` 등 기록 제외는 `skipped`).
모델 엔드포인트 미설정은 모델 기능을 비활성화하고 `model_endpoint_unset`을 알리며, 그 사유만으로 회색이 되지 않습니다.

## 2. 탐지 엔진 계층 구조

서버는 아래 탐지 결과를 모아 내용 기준으로 판정합니다.

```
프롬프트 입력
    │
    ▼
① 내장 정규식 탐지 (항상 실행, 비활성화 불가)
    └─ 26종 규칙: 주민번호·여권·카드번호·JWT·AWS 키·비밀번호 등
    └─ 단순 패턴 매칭 외 추가 검증(Luhn 체크섬, 주민번호 날짜 유효성)
    │
    ▼
② 사용자 추가 규칙 (대시보드 > 검사 서버 관리 > 사용자 규칙)
    ├─ 키워드 규칙: 금지 단어 목록 매칭
    └─ 정규식 규칙: Python/JS 호환 정규식, 최대 4,000자
    │
    ▼
③ Jev (로컬 모델, 내부 API 필드 context_detectors)
    └─ 정규식으로 판단하기 어려운 의미 기반 기준
       예) "미공개 연구 결과", "내부 프로젝트명"
    │
    ▼
④ 조직 규칙 (대시보드 활성 설정을 읽는 조직 서버)
    ├─ 메트릭 설정의 활성 태그 pythonRegex
    └─ Jev 설정의 프롬프트·출력 태그·jevThreshold
    │
    ▼
최종 신호 합산
    └─ 가장 심각한 action이 전체 신호 결정
       (block > mask > warn > allow)
```

## 3. 판정 기준(action) 설명

각 탐지 규칙에는 `action`이 있습니다.

| action | 동작 | 신호등 |
|--------|------|--------|
| `block` | 정제 시 자동 치환하지 않음. 검사 완료 후 확인하면 강행 전송 가능 | 🔴 RED |
| `mask` | 해당 구간을 `[TOKEN_N]`으로 치환 후 재검사. 원문도 확인 후 강행 전송 가능 | 🔴 RED (치환 전) |
| `warn` | 사용자 확인 후 전송, 정제 시 치환 대상 | 🟡 YELLOW |
| `allow` | 탐지 사실만 기록, 전송 허용 | 🟢 GREEN |

## 4. 내장 규칙 분류 (`server/policies/default.yaml`)

내장 26종 규칙은 아래 카테고리로 분류됩니다. 이 파일에서 `action`과 `severity`를 읽으며, 내장 유형의 조치 편집 UI는 아직 없습니다.

| 카테고리 | 포함 규칙 | 기본 action |
|----------|-----------|-------------|
| `personal_id` | 주민번호, 여권, 운전면허 | `mask` |
| `personal` | 전화번호, 이메일, 주소, URL 개인정보 | `mask` / `warn` |
| `financial` | 카드번호, 계좌번호 | `mask` |
| `credential` | AWS 키, GitHub 토큰, JWT, 개인키, 비밀번호 | `mask` |
| `infrastructure` | 내부 IP/도메인 (공개 IP는 `allow`) | `warn` / `allow` |
| `security` | CVE 번호 | `allow` |

> **설정 관리:** 사용자 규칙·Jev·모듈·조직 설정·모델 모드는 대시보드에서 관리합니다. env·YAML은 초기 구성의 기준이며, 저장된 ruleset·모델 모드가 우선합니다. 내장 유형 정책은 현재 `default.yaml` 수정 후 서버 재시작이 필요합니다.

## 5. 전송 목적지 안내 (`server/policies/destinations.yaml`)

목적지(외부 AI 서비스)의 데이터 정책을 등급과 근거로 제공합니다. 응답의 `destination`과 `destination_*` 알림, 규칙 묶음의 `destinations`는 안내용이며 내용 판정에 쓰지 않습니다.

| 등급 | 안내 근거 예시 |
|------|----------------|
| `standard` | 기업 계약 등 기본 학습 안 함이 확인된 경로 |
| `elevated` | 학습 opt-out 방식·소비자 경로·확인 불가 |
| `restricted` | 정책 문서 충돌·승인 범위 밖 저장 국가 |

목적지를 알 수 없을 경우 안내 등급은 `elevated`입니다. 등급이 달라도 같은 내용의 신호는 같습니다.

## 6. 대시보드에서 가능한 커스터마이징

**검사 서버 관리**(`/settings/guard`)에서 상태·사용자 규칙·Jev 판단 기준·조직 설정·사용자 연결을 관리합니다. 브라우저는 대시보드 백엔드의 `/api/v1/guard/**`를 호출하고, 백엔드가 관리 키를 붙여 서버 `/v1/admin/**`로 전달합니다.

### 6-1. 사용자 추가 규칙

- **키워드 규칙**: 금지 단어 목록을 직접 입력
- **정규식 규칙**: Python/JS 호환 정규식 패턴 (최대 4,000자, 중첩 수량자 금지)
- `distribute: false` 옵션으로 서버 전용(키워드 자체가 기밀인 경우) 배포 가능
- **Jev 판단 기준**: 기준·예문·제외 예문과 공통 프롬프트를 편집·시험. 내부 API 이름 `context_detectors`, `/v1/admin/context-detectors`는 유지하며 조직 트리의 Jev 설정과 별도로 관리
- **상태**: 모델 모드·모듈 사용 여부를 저장. 모델 엔드포인트 미설정·비활성을 표시

### 6-2. 태그 트리 계층화

- 태그를 부모-자식 구조(`parentId`)로 분류하여 감지 영역을 계층화
- 최상위 태그는 자신과 하위 태그의 감지 영역을 중복 없이 집계
- 트리 편집: 메트릭 설정 > 태그 탭에서 부모 지정/순서 변경 가능
- 활성 태그의 `pythonRegex`와 별도 **Jev 설정**(`/settings/jev`)의 프롬프트가 조직 검사에 적용됨
- 태그 정규식은 최대 4,000자. 검사 서버가 설정되면 변경된 비어 있지 않은 패턴을 저장 전에 `/v1/admin/org/regex/check`로 검증하고 실패 시 거부. 기존에 건너뛴 규칙은 메트릭 설정·검사 서버 상태·전체 현황 배너에 태그 이름과 사유 표시

### 6-3. 정책 상태(PolicyState)

- 메트릭 설정에서 이름·색을 정하는 거버넌스 분류 레이블이며 신호등 판정과 별개
- 검사 서버 관리 > 조직 설정의 `policy_state_map`으로 `allow`·`warn`·`block`을 활성 대시보드 버전의 정책 상태 ID에 명시적으로 연결
- 기본값은 모두 `null`(연결 안 함). 활성 버전에 없는 ID는 기록에 보내지 않으며 이름·색으로 판정값을 추론하지 않음
