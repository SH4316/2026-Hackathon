# 사이버보안 분야 전체 분류 및 확장

기존에 정리하신 목록은 보안 탐지·대응, 애플리케이션 보안, 데이터 보호, 공격 표면 관리, 이메일 보안, 보안 운영 자동화를 중심으로 구성되어 있습니다.

여기에 IAM·PAM 같은 인증 및 접근 제어, 네트워크 보안, 클라우드 보안, 취약점 관리, 복구 체계, 보안 거버넌스 등을 추가하면 기업 정보보안 전반을 포괄하는 분류 체계를 구성할 수 있습니다.

분류 기준은 NIST CSF 2.0의 6개 기능인 Govern, Identify, Protect, Detect, Respond, Recover를 참고하되, 실제 보안 제품 및 기술을 파악하기 쉽도록 세부 영역으로 나누었습니다.&#x20;

## 1. 엔드포인트 보안 (Endpoint Security)

PC, 서버, 모바일 기기 등 개별 장비를 보호하고 위협을 탐지하는 분야입니다.

| 기술                  | 구분 | 주요 역할                   |
| ------------------- | -- | ----------------------- |
| EPP                 | 추가 | 악성코드 실행 및 감염 예방         |
| AV/NGAV             | 추가 | 기존·신종 악성코드 탐지 및 차단      |
| EDR                 | 기존 | 개별 기기 행위 감시, 위협 조사 및 대응 |
| UEM/MDM             | 추가 | PC·모바일 기기 정책 및 보안 상태 관리 |
| Application Control | 추가 | 허가된 프로그램만 실행하도록 제한      |
| Endpoint Hardening  | 추가 | OS·기기 보안 설정 강화          |
| Disk Encryption     | 추가 | 디스크 분실·도난에 따른 정보 노출 방지  |

## 2. 통합 위협 탐지 및 대응 (SOC / Detection & Response)

여러 시스템에서 발생하는 보안 이벤트를 수집하고 공격을 분석·대응하는 분야입니다.

| 기술                   | 구분 | 주요 역할                                      |
| -------------------- | -- | ------------------------------------------ |
| XDR                  | 기존 | 엔드포인트·네트워크·클라우드·이메일 등 여러 영역의 위협 연계 탐지 및 대응 |
| MDR                  | 기존 | 전문 인력이 탐지·분석·대응을 제공하는 관리형 서비스              |
| SIEM                 | 기존 | 로그 중앙 수집·검색·상관분석·경보                        |
| SOAR                 | 기존 | 보안 대응 절차와 도구 연동 자동화                        |
| TIP                  | 기존 | 외부·내부 위협 인텔리전스 수집 및 관리                     |
| Incident Response    | 기존 | 침해사고 조사·격리·제거·복구                           |
| SOC                  | 추가 | 보안 이벤트를 지속적으로 감시하는 운영 조직 또는 기능             |
| NDR                  | 추가 | 네트워크 트래픽 기반 위협 탐지 및 대응                     |
| UEBA                 | 추가 | 사용자·장비의 비정상 행동 분석                          |
| ITDR                 | 추가 | 계정·인증·권한 체계에 대한 공격 탐지 및 대응                 |
| Threat Hunting       | 추가 | 경보에 나타나지 않은 잠재적 침해 능동 탐색                   |
| DFIR                 | 추가 | 디지털 포렌식 및 침해사고 대응                          |
| Threat Intelligence  | 추가 | 공격자·전술·취약점 악용 정보 분석                        |
| Deception Technology | 추가 | 허니팟·미끼 자산으로 공격자 행동 유도 및 탐지                 |

EDR은 단말 내부에 집중하고, XDR은 여러 보안 영역의 데이터를 연계합니다. SIEM은 광범위한 이벤트 수집·분석에 중점을 두며, MDR은 이러한 기술을 활용해 전문 인력이 운영하는 서비스 모델입니다. 이들은 완전히 대체 관계가 아닙니다.&#x20;

## 3. 애플리케이션 보안 (Application Security / DevSecOps)

소프트웨어 설계, 개발, 빌드, 배포, 운영 과정에서 취약점을 찾아 예방하는 분야입니다.

| 기술                             | 구분 | 주요 역할                                     |
| ------------------------------ | -- | ----------------------------------------- |
| SCA                            | 기존 | 오픈소스·외부 라이브러리의 취약점 및 라이선스 분석              |
| SAST                           | 기존 | 소스코드 정적 취약점 분석                            |
| DAST                           | 기존 | 실행 중인 애플리케이션에 대한 동적 보안 테스트                |
| ASPM                           | 기존 | 애플리케이션 보안 진단 결과 통합·위험 우선순위 관리             |
| IAST                           | 추가 | 애플리케이션 실행 중 내부 동작을 활용한 보안 분석              |
| RASP                           | 추가 | 실행 중인 애플리케이션 내부에서 공격 탐지·방어                |
| API Security                   | 추가 | API 인증·인가·노출·남용 탐지 및 보호                   |
| Secrets Scanning               | 추가 | 코드에 포함된 API 키·비밀번호·토큰 탐지                  |
| IaC Scanning                   | 추가 | Terraform·Kubernetes 매니페스트 등 인프라 정의 코드 검사 |
| Container Scanning             | 추가 | 컨테이너 이미지 및 패키지 취약점 검사                     |
| SBOM                           | 추가 | 소프트웨어 구성요소 목록 생성·관리                       |
| Software Supply Chain Security | 추가 | 빌드·패키지·서명·배포 과정의 무결성 확보                   |
| CI/CD Security                 | 추가 | 코드 저장소·빌드 파이프라인·배포 권한 보호                  |
| Threat Modeling                | 추가 | 설계 단계에서 위협 및 공격 경로 식별                     |
| Secure SDLC / SSDF             | 추가 | 개발 생명주기 전반의 보안 요구사항과 통제 관리                |

SAST·DAST·SCA 등은 개별 진단 기법이고, ASPM은 여러 진단 결과를 연계하여 애플리케이션 위험을 관리하는 상위 기능입니다.&#x20;

## 4. 인증 및 접근 제어 (Identity & Access Security)

사용자, 관리자, 서비스 계정의 신원을 확인하고 리소스 접근 권한을 통제하는 분야입니다.

현재 목록에서 가장 크게 누락된 영역 중 하나입니다.

| 기술                           | 주요 역할                       |
| ---------------------------- | --------------------------- |
| IAM                          | 사용자·서비스 계정의 인증과 접근 권한 관리    |
| IdP                          | 사용자 신원을 확인하고 인증 정보를 제공      |
| SSO                          | 한 번의 인증으로 여러 서비스에 접근        |
| MFA / FIDO2                  | 다중 요소 및 피싱 저항성 인증           |
| PAM                          | 관리자·고권한 계정 접근 통제            |
| PIM                          | 필요할 때만 특권을 부여하고 회수          |
| IGA                          | 계정 생성·퇴사 처리·권한 승인 및 정기 검토   |
| CIAM                         | 고객·외부 사용자 대상 인증 및 계정 관리     |
| ISPM                         | 계정·권한 설정의 위험 상태 관리          |
| ITDR                         | 계정 탈취·권한 상승·인증 공격 탐지 및 대응   |
| NHI Security                 | 서비스 계정·워크로드·머신 ID 보호        |
| Secrets Management           | 비밀번호·API 키·서비스 자격증명 관리      |
| PKI / Certificate Management | 공개키 인증서 발급·검증·갱신·폐기         |
| Zero Trust Architecture      | 위치와 무관하게 신원·기기·상황에 따라 접근 통제 |

예를 들어 Keycloak은 IAM·IdP·SSO·CIAM 기능을 구현하는 데 활용할 수 있지만, 별도 PAM·IGA 제품이 제공하는 모든 기능을 대체하지는 않습니다.

NIST의 Zero Trust Architecture도 네트워크 위치만으로 신뢰하지 않고 사용자·기기·서비스 신원과 권한을 검증하는 구조를 강조합니다.&#x20;

## 5. 네트워크 및 경계 보안 (Network Security)

네트워크 접근을 제한하고, 트래픽을 검사하며, 내부 침투와 공격 확산을 방지하는 분야입니다.

| 기술                | 주요 역할                             |
| ----------------- | --------------------------------- |
| NGFW              | 애플리케이션 인식 및 정책 기반 차세대 방화벽         |
| IDS / IPS         | 침입 탐지 및 차단                        |
| WAF               | HTTP 기반 웹 공격 탐지 및 차단              |
| WAAP              | 웹 애플리케이션·API에 대한 통합 보호            |
| DDoS Protection   | 대규모 트래픽 기반 서비스 거부 공격 방어           |
| DNS Security      | 악성 도메인 접근·DNS 기반 공격 방어            |
| NAC               | 네트워크에 연결되는 기기의 접근 통제              |
| NDR               | 네트워크 행위 기반 공격 탐지 및 대응             |
| ZTNA              | 사용자·기기별 최소 권한 애플리케이션 접근           |
| SASE              | 네트워크 연결과 클라우드 보안 기능을 통합한 아키텍처     |
| SSE               | SWG·CASB·ZTNA 등 클라우드 기반 보안 서비스 통합 |
| SWG               | 웹 접속 및 유해 사이트 접근 제어               |
| FWaaS             | 클라우드 기반 방화벽 서비스                   |
| Microsegmentation | 시스템·워크로드 간 통신을 세밀하게 분리            |
| RBI               | 원격 브라우저 격리로 웹 콘텐츠 위험 완화           |

## 7. 데이터 및 암호화 보안 (Data Security)

민감정보를 찾아내고 보호하며, 데이터 접근과 유출을 관리하는 분야입니다.

| 기술                              | 구분 | 주요 역할                    |
| ------------------------------- | -- | ------------------------ |
| DSPM                            | 기존 | 민감 데이터 위치·노출·접근 위험 분석    |
| DLP                             | 기존 | 민감정보의 비인가 반출 탐지 및 차단     |
| Encryption Key Management       | 기존 | 암호화 키의 생성·보관·교체·폐기       |
| KMS                             | 추가 | 암호화 키 수명주기 중앙 관리         |
| HSM                             | 추가 | 하드웨어 기반 암호화 키 보호 및 암호 연산 |
| Data Discovery / Classification | 추가 | 민감 데이터 발견·분류·등급 지정       |
| DAM                             | 추가 | 데이터베이스 접근 및 활동 모니터링      |
| Data Masking / Tokenization     | 추가 | 민감 데이터의 원본 노출 최소화        |
| IRM / DRM                       | 추가 | 파일·문서 사용 권한 및 유통 통제      |
| Data Access Governance          | 추가 | 데이터 접근 권한 검토 및 관리        |
| Privacy Management              | 추가 | 개인정보 처리·보유·삭제·규정 준수 관리   |

DSPM과 DLP의 핵심 차이: DSPM은 데이터가 어디에 있으며 얼마나 위험하게 노출되어 있는지 파악하고, DLP는 데이터가 허가되지 않은 경로로 유출되는 것을 막는 데 중점을 둡니다.

## 8. 자산·공격 표면·취약점 관리 (Exposure Management)

조직이 보유한 자산을 발견하고, 공격자가 악용할 수 있는 취약점 및 공격 경로를 식별하는 분야입니다.

| 기술                            | 구분 | 주요 역할                      |
| ----------------------------- | -- | -------------------------- |
| ASM                           | 기존 | 조직 전체 공격 표면 식별·관리          |
| EASM                          | 기존 | 인터넷에 노출된 외부 자산과 위험 탐색      |
| CASM                          | 기존 | 사이버 공격 표면의 지속적인 식별·관리      |
| CAASM                         | 추가 | 여러 보안 도구의 자산 정보를 통합·분석     |
| Asset Inventory / CMDB        | 추가 | 하드웨어·소프트웨어·서비스 자산 목록 관리    |
| Vulnerability Management (VM) | 추가 | 취약점 발견·분류·우선순위·조치 추적       |
| Patch Management              | 추가 | 운영체제·애플리케이션 보안 패치 관리       |
| CTEM                          | 추가 | 지속적인 위협 노출 평가·우선순위화·검증·개선  |
| Attack Path Analysis          | 추가 | 공격자의 권한 상승·횡적 이동 경로 분석     |
| BAS                           | 추가 | 알려진 공격 기법을 모의 실행해 방어 효과 검증 |
| Penetration Testing / PTaaS   | 추가 | 실제 공격 기법을 사용한 침투 가능성 검증    |
| Red Teaming                   | 추가 | 현실적인 공격 시나리오를 통한 조직 방어 검증  |
| Bug Bounty / VDP              | 추가 | 외부 연구자의 취약점 제보·처리 체계       |

CASM은 Cyber Attack Surface Management라는 의미로 사용되기도 합니다. CAASM(Cyber Asset Attack Surface Management)은 내부 자산 정보를 여러 도구에서 통합하는 데 더 중점을 둡니다. EASM은 외부에서 노출되는 자산을 탐색합니다.&#x20;

## 9. 이메일 및 사용자 보안 (Email & Human Security)

피싱, 악성 첨부파일, 계정 사칭과 사람의 실수에 의한 보안 사고를 예방합니다.

| 기술                             | 구분 | 주요 역할                     |
| ------------------------------ | -- | ------------------------- |
| SEG                            | 기존 | 이메일 게이트웨이에서 스팸·악성코드·피싱 검사 |
| Email Security / Anti-Phishing | 기존 | 메일 기반 위협 탐지 및 차단          |
| Phishing Simulation            | 기존 | 모의 피싱 공격으로 사용자 대응 수준 평가   |
| SPF / DKIM / DMARC             | 추가 | 발신 도메인 인증 및 이메일 사칭 방어     |
| BEC Protection                 | 추가 | 거래처·관리자 사칭 및 송금 사기 탐지     |
| Security Awareness Training    | 추가 | 임직원 대상 보안 인식·대응 교육        |
| Email DLP                      | 추가 | 이메일을 통한 민감정보 반출 방지        |

SEG는 이메일 보안의 한 종류입니다. 이메일 보안은 게이트웨이뿐 아니라 계정 탈취 탐지, 메일함 내부 분석, 발신 도메인 인증까지 포함할 수 있습니다.

## 10. 백업·복구·보안 복원력 (Cyber Resilience)

보안 사고가 발생한 이후 시스템과 사업 운영을 회복하는 분야입니다.

## 14. 기존 목록에서 중요하게 누락된 분야

전체를 한 번에 구축할 필요는 없지만, 기존 목록의 기술적 공백을 기준으로 우선 검토할 영역은 다음과 같습니다.

| 우선순위 | 분야                                   | 중요성                 |
| ---- | ------------------------------------ | ------------------- |
| 1    | IAM / MFA / PAM                      | 계정 탈취 및 권한 오남용 통제   |
| 2    | Asset Inventory / CAASM              | 보호 대상 자산과 미관리 자산 파악 |
| 3    | Vulnerability / Patch Management     | 발견된 취약점을 실제로 해결     |
| 4    | Network Security / WAF               | 시스템 접근과 외부 공격 차단    |
| 5    | CSPM / CNAPP                         | 클라우드 설정·권한·워크로드 보호  |
| 6    | Backup / DR / BCP                    | 사고 발생 이후 복구 능력 확보   |
| 7    | GRC / ISMS                           | 조직 차원의 보안 기준과 책임 확립 |
| 8    | Secrets / PKI Management             | 인증정보 및 암호화 자산 보호    |
| 9    | API / Software Supply Chain Security | 애플리케이션과 배포 과정 보호    |
| 10   | CTEM / Security Validation           | 실제 악용 가능성과 방어 효과 검증 |

위 우선순위는 기존 목록 대비 일반적인 기업 IT 환경의 기능적 공백을 기준으로 한 것입니다. 실제 도입 순서는 자산 구성·사업 위험·규제 요건에 따라 달라집니다.

마지막으로 질문의 표기 중 `ㄴㅁㄴㅆ`, `ㅇㅁㄴㅆ`은 한영 입력 오류로 보고 각각 SAST, DAST로 해석하였습니다. `ㄴㅊㅁSCA`는 SCA로 분류하였으며, 단독으로 기재된 `P`는 의미가 명확하지 않아 별도 기존 분야로 확정하지 않았습니다. 침투 테스트를 의미한 경우에는 위의 Penetration Testing에 해당합니다.

핵심적으로, 기존 목록은 위협을 찾아내고 분석하는 기술에 강점이 있습니다. 완전한 보안 체계로 확장하려면 여기에 신원·접근 통제, 자산·취약점 관리, 네트워크·클라우드 방어, 사고 복구, 조직 거버넌스를 결합해야 합니다.
