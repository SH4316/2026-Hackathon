# 탐지 정확도 평가

## 데이터

Kaggle "The Learning Agency Lab – PII Data Detection" 대회 데이터(학생 에세이 + 토큰별 BIO 라벨).

- `kaggle_train.json`: 6,807개 문서, 라벨 있음 → 평가에 사용
- `kaggle_test.json`: 10개 문서, **라벨 없음**(대회 제출용) → 평가 불가
- 라벨: NAME_STUDENT, EMAIL, USERNAME, ID_NUM, PHONE_NUM, URL_PERSONAL, STREET_ADDRESS
- 개인정보는 원 데이터에서 가짜 값(Faker 등)으로 바뀌어 있습니다.

**데이터 파일은 저장소에 올리지 않습니다**(대회 데이터 라이선스·용량). Kaggle 에서 내려받아 이 폴더(`server/eval/`)에 두면 되고 `.gitignore` 로 제외됩니다.

## 실행

```powershell
cd server
python eval/run_eval.py --data eval/kaggle_train.json --split dev --errors 10
python eval/run_eval.py --data eval/kaggle_train.json --split all --json eval/result-all.json
```

- `--split`: `dev`(문서 번호 % 10 < 7, 규칙 조정용) | `holdout`(나머지, 최종 확인용) | `all`
- `--errors N`: 유형별 누락·오탐 사례를 구간 주변만 N개 출력

## 지표

- **예측**: 조치가 `allow` 가 아닌 탐지(경고·치환·차단으로 이어지는 것), 목적지 미상 기본 등급 기준
- **TP**: 정답 구간과 겹치는 예측이 있음 / **FN**: 없음 / **FP**: 어떤 정답과도 겹치지 않는 예측
- **오답률** = (FP + FN) / (TP + FP + FN) — 정밀도와 재현율이 모두 높아야 낮아짐
- **형식 기반 유형**(오답률 대상): EMAIL, PHONE_NUM, ID_NUM, STREET_ADDRESS
- **문맥 유형**(재현율만 보고): NAME_STUDENT, URL_PERSONAL, USERNAME — 인용 저자·참고 링크·일반 단어와 문맥으로만 구별됨.
  이 데이터의 개인 URL 대부분은 임의 도메인(`jacobs-fisher.com/listpost.html` 등)이라 형식만으로 참고 URL 과 구별되지 않습니다.
- 문서 기밀 표식(`confidential_marker`)은 개인정보가 아니어서 오탐에서 빼고 따로 셉니다.
- **문서 단위**: 형식 기반 개인정보가 있는 문서를 경고했는지(누락률), 개인정보가 전혀 없는 문서를 경고했는지(오경고율)

### 조정 과정

| 단계 | dev 오답률 | 변경 |
|---|---|---|
| 기존 규칙 | 89.6% | 한국 형식 위주, 미국 전화·식별번호·주소 규칙 없음, 키워드 "Confidential" 이 "confidentially" 오탐 41건 |
| 1차 | 19.1% | 북미·국제 전화, 식별번호(키워드·장자리 숫자), 미국·한국 주소, 프로필 URL, 아이디 키워드 규칙 추가, 키워드 영단어 경계 |
| 2차 | 8.1% | `:` 뒤 숫자 허용, URL 파라미터·`_` 뒤 숫자 제외, 주소 접미사 `Sq` 제거 |
| 3차 | 4.65% | 8자리 숫자 허용(유효 날짜 YYYYMMDD 제외) |
| 4차 | 4.65% | 식별번호 키워드 콜론 주변 여러 공백 허용, @핸들 규칙 제거(개인 아이디 0건, 기관명 오탐만) |

holdout 은 3차 이후 처음 확인했고, 그 뒤에는 일반화되는 수정(공백 허용, 오탐만 내는 규칙 제거)만 했습니다.
holdout 의 남은 오류는 강의 케이스 번호(`UVA-IV-8322`), `ROLL VZ:775Y6A5764`, `Sub Code : 06EYD876` 같은 개별 표기와,
식별번호처럼 보이지만 라벨이 없는 12자리 숫자 2건입니다. 이를 맞추는 규칙은 이 데이터에만 맞춰지므로 넣지 않았습니다.

## 한계와 다음 단계

- 정답 수가 적어(전화 6, 주소 2) 유형별 수치의 변동이 큽니다.
- 학생 이름·개인 URL·아이디는 로컬 모델 문맥 탐지기로 평가해야 합니다(모델 확정 후).
- 이 데이터는 영어·미국 형식입니다. 한국 형식(주민번호·한국 전화·도로명 주소)은 합성 평가셋이 따로 필요합니다.
